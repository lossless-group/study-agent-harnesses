# Tome Joins the Agent-Harnesses Study

## Why Care?

Every harness in this study loads skills from its own folder. [Tome](https://tome-mcp.com/) keeps one library and wires it into all of them: it writes each harness's MCP config and a fenced block in its rules file, then lets the agent search and load one skill at a time over MCP. That is the problem our `agent-skills` symlink script and GNU Stow solve, done differently, and the nearest thing we've found to context-v.dev.

## What changed

- **Pinned** `devrelaicom/tome` as a shallow submodule at `e7974c1` (crate version 0.7.18).
- **Profiled** it in `context-v/profiles/Profile__Tome.md`, citing source for the index schema, the three-tier routing directive, the `<!-- tome:begin/end -->` rules block, and the MCP tools.
- **Added** a row to the README's design-space table.

## Worth knowing

Tome's homepage says "no telemetry", but the code ships anonymous telemetry that is on until you run `tome telemetry off`. The site's version badge also lags the crate (v0.6.0 against 0.7.18). Both are recorded in the profile.
