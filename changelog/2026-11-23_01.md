# Agent-Harnesses Pins Move to November 2026; Profiles Catch Up

## Why Care?

This study reads harness source code instead of trusting what people say about it. That only works if the pinned code is current. Most pins dated from July 2026, and four months was enough for several of the profiles' headline findings to stop being true. Every submodule now points at the head of its upstream default branch, and every profile says what changed.

## What's New?

- **AutoGen is archived.** Microsoft replaced the "maintenance mode" banner with "archived and no longer maintained," with no bug or security fixes. The code did not change, so the profile still holds as a reference.
- **OpenHands is now a frontend only.** Two weeks after the July pin, upstream deleted the Python app-server and replaced the repo with the Agent Canvas React/Electron frontend. The event stream, MCP router, and webhook code the profile described now live in `OpenHands/software-agent-sdk`, which this study does not pin.
- **Pi built MCP into its core.** The profile's lede was that Pi refuses MCP, sub-agents, permission popups, and plan mode, then ships each as an example extension. Since v0.99.0, MCP is built in on Pi's own `pi-mcp` client. Sub-agents and plan mode are still examples only.
- **Codex dropped its MCP server mode** and now describes its Linux sandbox as bubblewrap plus seccomp, with Landlock kept only as a legacy option. The two-axis model (sandbox profile vs. approval policy) still holds.
- **Goose moved its agent loop into `oi-kit`**, a set of reusable crates in the same repo, and cut its extension variants from six to four. Builtin and Platform extensions still run in-process.
- **OpenCode deleted `packages/opencode/` and `CONTEXT.md`.** Its modules moved into `packages/core/`. It now has 64 SQLite migrations, up from 38, and still no Go.
- **The MCP Python SDK shipped stable v2** and added a Skills extension for serving agent skills over MCP, which sits close to what Tome does.
- **Cline** now says outright that per-project MCP is a declined design: plugins are discovered only from the home directory "so opening a repository cannot activate repository-controlled MCP servers."
- Aider and Tome had no new commits. Continue had three docs commits and none since 2026-07-20.

## How it was done

For each repo: read the commit log and release tags between the old and new pins, read the changelog where one exists, then re-checked every path the profile cites at the new SHA. Line-number citations were re-located. Where a whole section described code that no longer exists, the section was kept as a record of the July pin and marked as such, so the earlier reasoning is not lost. Each profile gained a "Changes since the previous pin" section, and the README gained a pin-refresh table.

## Worth knowing

Ledes were rewritten for Codex, the MCP Python SDK, OpenCode, OpenHands, and Pi, and the profiles index matches. The OpenHands profile's frontmatter `license` and `package` keys still describe the July pin; the body says so.
